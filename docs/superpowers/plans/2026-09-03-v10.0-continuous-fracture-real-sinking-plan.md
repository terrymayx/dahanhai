# V10.0 Continuous Fracture and Real Sinking Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Upgrade V9.9 into V10.0 with continuous crack propagation, bending-moment hull failure, gravity-biased compartment flow, realistic capsize/deck immersion, persistent chunk physics, and continuous breach visuals.

**Architecture:** Keep V9.9 as the authoritative material/compartment/buoyancy foundation. Add focused V10 modules that consume V9.9 state and expose small interfaces; expensive work remains event-driven while per-frame work is limited to fixed-size caches (12 bending sections, 4–8 compartments, <=18 chunks).

**Tech Stack:** Vanilla JavaScript, HTML5 Canvas, GitHub Pages, Node.js assertion-based regression tests, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-09-03-v10.0-continuous-fracture-real-sinking-design.md`

## Global Constraints

- Continue using 8px logical physical cells.
- One cannonball still collides with only the foremost live physical cell; ricochet may continue, but one impact never penetrates multiple layers.
- Preserve manual cannon attack 24–240, AUTO, and attack-scaled explosion radius.
- No V10 module may iterate all `ship.cells` every frame.
- Crack propagation radius <= 10 and <= 18 processed nodes per event.
- Bending uses exactly 12 cached longitudinal sections.
- Structural chunks remain globally capped at 18; chunk collision resolves at most 24 candidate pairs per frame.
- Compartments remain 4–8 per ship.
- Breach visual cache rebuilds only on topology/material/crack revision changes.
- Release cache version is `10.0.0`.

# V10.5 Persistent Crew & Deck Combat Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Upgrade V10.4 boarding into a persistent real-crew system where visible crew exist throughout naval combat, can be killed by real spatial damage, affect ship performance, and transition into the existing boarding flow without respawning.

**Architecture:** Keep V10.3 broadside and V10.4 boarding as the stable naval/boarding foundations. Add focused V10.5 modules for persistent crew state, posts/staffing, crew AI/combat, spatial crew damage, naval-system bridges, and rendering; use narrow wrappers/delegation hooks instead of rewriting `30_battle.js` or replacing the physical ship grid. During boarding, `state.boarding.captain/allies/boarders` become references to persistent crew entities so V10.4 state/camera/nav remain the source of truth while V10.5 owns who those people are and whether they survive.

**Tech Stack:** Vanilla JavaScript, Canvas 2D, existing V8/V9/V10 ship-grid physics, V10.3 broadside API, V10.4 boarding API, Node.js assertion tests, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-09-03-v10.5-persistent-crew-deck-combat-design.md`

## Global Constraints

- Version title: `大航海时代 V10.5 · 持久船员与甲板近战`.
- Cache/version query: `10.5.0` on every script in `index.html`.
- Player roster target: captain ×1, gunner ×4, sailor ×5, helmsman ×1 (about 11 total).
- Enemy roster target: Sloop 5–7, Gunship 8–11, Manowar 11–15.
- Player crew never pathfinds or boards onto enemy ships.
- Only enemy crew explicitly marked as boarders may change `currentShipId` to the player ship during active boarding.
- Player captain is AI-controlled during naval combat; during boarding the player controls movement only.
- Captain attacks automatically only when an enemy is already in attack range; captain never auto-paths or auto-chases.
- Enemy boarder combat classes are swordsman, archer, elite captain; archers must board the player deck before shooting.
- Crew death is permanent for the current battle and never replenishes after boarding.
- Real spatial damage only: no random crew-death roll disconnected from projectile/explosion/fire/chunk position.
- Gunner loss changes real V10.3 gun-group availability/reload; helmsman loss changes real turning; sailor loss changes replacement labor, defense count, and V10.5 firefighting efficiency.
- Preserve one-shell-one-foremost-live-layer projectile behavior and all V10.2 ammo semantics.
- Preserve V10.4 boarding state machine: `navalCombat → boardingApproach → boardingLocked → boardingWave → boardingRetreat → navalCombat`.
- Keep `30_battle.js` stable; integrate by isolated V10.5 modules and narrow wrappers.
- Non-boarding crew AI decision rate: 4–6 Hz. Boarding AI decision rate: 8–12 Hz. Render interpolation remains frame-rate driven.
- Screen active-crew hard cap: 45. No ragdoll, skeletal animation, cloth/rope physics, doctor, repairman, equipment, skill tree, prisoner, or player boarding in V10.5.

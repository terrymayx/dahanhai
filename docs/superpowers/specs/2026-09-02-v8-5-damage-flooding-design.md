# V8.5 · 船体损伤与进水系统设计

## 目标
把 V8.4.2 的“方块有耐久”升级为可读、可累积、可产生沉船后果的完整损伤链：完整 → 裂纹 → 严重破损 → 掉块 → 进水/结构断裂 → 沉没。

## 已批准范围
1. 方块损伤阶段可视化。
2. 水线外壳破洞产生 leak，持续进水；进水降低速度并增加吃水，达到阈值后沉没。
3. 炮弹必须先破甲：未摧毁当前格时，大部分动能被吸收；摧毁后才允许剩余穿透继续命中内部格。
4. 主梁被打断后，依赖现有连通性系统制造更大的结构脱落和 debrisCluster。

## 约束
- 保留 V8.4.2：2 发低频齐射、无镜头抖动、无受击船体后坐/横摇、自然海浪浮动。
- 保留点击锁定、双舰编队、火药舱、材料差异、残骸浮沉、落水水花。
- 不新增第三艘船、关卡、登船战。

## 方块损伤阶段
每格继续使用 `hp/maxHp`。新增 `damageStage(cell)`：
- `intact`: hp/maxHp > 0.75
- `cracked`: 0.50 < ratio <= 0.75
- `critical`: 0 < ratio <= 0.50
- `destroyed`: hp <= 0 / !alive
Renderer 用缺角、裂纹、焦黑和局部透明变化表达，不显示每格血条。

## 破甲与穿透
玩家炮弹仍有 penetration，但材料消耗改为分两段：
- 格子未被本次命中摧毁：炮弹停止，视为装甲吸收。
- 格子被摧毁：从 penetration 扣除该材料阻力；若剩余 penetration > 0，则推进到格后继续飞行。
因此连续炮击同一区域会从“打裂外壳”逐渐过渡到“破口后钻入内部”。

## 进水
每艘船新增：
- `flooding`: 当前进水量 0..1
- `leaks`: 破洞记录
- `draft`: 吃水视觉量 0..1

只对 `hull` 方块在被摧毁时创建 leak。水线判定使用局部坐标中心区域：敌舰取局部 Y 接近船体中线的外壳；玩家竖向船体取局部 X 接近中线的外壳。每个 leak 有固定速率，按破洞数量叠加。

更新规则：
- flooding 每秒按 leak 总速率增长。
- 敌舰速度乘 `1 - flooding*0.55`，最低保留基础速度约 25%。
- draft 随 flooding 增加，Renderer 将船体向水中下压。
- flooding >= 1 触发沉没；玩家同样可因 flooding 达 1 失败。

## 主梁断裂
沿用 `detachDisconnectedComponents()`。主梁/核心格毁坏后立即重新计算连通块；若出现多格断块，优先创建 coherent debrisCluster。结构断裂的视觉强度按 detached cell 数增加，但继续保持 camera shake=0。

## 视觉
- cracked：细裂纹 + 轻微变暗。
- critical：明显缺角/焦黑 + 更强裂纹。
- leak：破洞附近周期性小泡沫/水纹。
- draft：整船逐步下沉，但不产生受击抖动。
- flooding 高时增加轻量水汽/泡沫，不新增全屏特效。

## 验收
- 未被打穿的 hull 能显示裂纹且炮弹停止。
- hull 被打穿后，后续/剩余动能能命中内部格。
- 水线 hull 掉块后 leaks 增加，flooding 随时间增长，速度下降并逐步下沉。
- flooding 达阈值会沉船。
- beam 被打断时可形成多格 coherent debrisCluster。
- V8.4.2 无抖动、2 发低频齐射继续成立。

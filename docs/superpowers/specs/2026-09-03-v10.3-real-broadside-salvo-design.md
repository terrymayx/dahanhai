# V10.3 · 真实舷炮齐射系统 — 设计规格

日期：2026-09-03

## 目标

V10.3 把当前“固定坐标生成 4 发炮弹”的齐射升级为真实左右舷炮组：每一门炮都有自己的物理炮位、左右舷归属、炮口位置、射界、装填状态和存活状态。炮位被击毁后，该门炮永久退出本轮战斗；船体角度不合适时只能打出部分齐射或完全无法开火。

本版本重点是“炮位真实化 + 舷侧射界 + 逐门点火 + 炮位损毁”，不引入弹药库存、船员装填、复杂航速/帆控或完整航海操船系统。

## 不可破坏的现有规则

1. 物理网格继续保持 8px。
2. 一发炮弹只命中最前一个活物理层；本炮打穿当前格后不能继续伤害第二活格。
3. 后续炮弹可以穿过真实存在的破口。
4. 玩家浅弧上限保持 32，敌舰浅弧上限保持 22。
5. V10.2 的实心弹、链弹、爆裂弹继续共用 24–240 炮攻。
6. 玩家当前弹种即时切换继续生效；敌舰继续使用 standard 普通弹。
7. V10.1 的裂缝、渐进断船、舱室进水、横倾、翻覆和大残骸系统全部继续生效。
8. 火焰 DOT 仍不受装甲或弹药倍率影响。
9. 全局炮弹/FX/残骸上限继续受现有性能约束。

## 现有问题

当前 `30_battle.js` 的玩家齐射使用固定 `SALVO_COUNT=4`，炮弹从 `x=610` 和三个固定 y 坐标之一生成；敌舰也从一个近似船体位置生成炮弹。它们不是从真实 `cannon` 物理格发射，因此：

- 炮位被毁只会减少粗粒度 `cannonsAlive`，不会精确少一门炮。
- 左舷和右舷没有独立状态。
- 船体角度与能否开火几乎无关。
- 齐射视觉不是沿一整排炮门依次点火。

V10.3 用独立 `V103Broadside` 子系统替换这些行为，但保留 Battle 的旧实现作为模块缺失时的 fallback。

## 总体架构

新增模块：

- `js/v8/35_v103_broadside.js`
  - 生成/同步左右舷炮组。
  - 将选定 deck/cannon 物理格绑定成真实炮位。
  - 计算炮口位置、左右舷、射界、装填和存活状态。
  - 建立玩家和敌舰逐门齐射队列。
  - 控制敌舰接近后转向横列。
  - 提供玩家转向输入的物理更新。

- `js/v8/49_v103_broadside_control.js`
  - 移动端左右转舵按钮。
  - 键盘 A/D、←/→ 支持。
  - 显示左/右舷存活炮数与装填状态。
  - 不与 V10.2 弹药按钮冲突。

修改：

- `js/v8/30_battle.js`
  - `startPlayerSalvo()`、`updatePlayerSalvo()`、`fireEnemy()` 在 V103 存在时委托给 Broadside。
  - `update()` 调用 V103 的航向/装填更新。
  - 旧 4 发固定齐射保留为 V103 缺失时 fallback，保证历史模块测试可单独运行。

- `js/v8/33_v972_player_attack.js`
  - 继续给每一门玩家炮生成的炮弹附加当前炮攻和当前弹药。

- `js/v8/41_render_v9.js`
  - 新增舷炮炮口烟、连续火光和有限后坐反馈 FX。

- `js/v8/47_v97_status_overlay.js`
  - 显示目标是否在当前舷侧射界、预计可开火门数、左/右舷存活炮数。

- `index.html`
  - 升级 V10.3，缓存键 `10.3.0`。

## 炮位数据结构

每艘活船初始化：

```text
ship.__v103Battery = {
  port: { guns: [...] },
  starboard: { guns: [...] }
}
```

每个 gun slot：

```text
{
  id,
  side: 'port' | 'starboard',
  cell,
  axial,
  muzzleLocal: {x,y},
  arcOffset,
  reload,
  reloadMax,
  lastShot
}
```

`cell` 必须指向真实 `ship.cells` 中的一个物理格。炮位存活条件只有：

```text
cell.alive === true && cell.type === 'cannon'
```

炮位格被击毁后，不生成替代炮，不把它从别处“补回来”。

## 每艘船的舷炮数量

第一版固定：

- 玩家旗舰：左舷 7 门，右舷 7 门。
- sloop：左舷 3 门，右舷 3 门。
- gunship：左舷 5 门，右舷 5 门。
- manowar：左舷 7 门，右舷 7 门。

这些炮位优先复用现有 cannon 格；不足时从中部 25%–75% 船长范围内选择靠近对应舷侧的 deck 格，并把它们提升为 cannon 物理格。

提升后的格使用当前 `CELL_HP.cannon`、`MATERIAL_RESISTANCE.cannon` 和 `critical/system='cannon'` 规则，因此 V10.2 链弹对 cannon 的 1.35×倍率自动生效。

## 舷侧定义

玩家船模板纵向布置：

- starboard：船体局部 +X。
- port：船体局部 -X。

敌舰模板横向布置：

- starboard：船体局部 +Y。
- port：船体局部 -Y。

目标先转换到船体局部坐标，由其横向坐标自动判定应该使用哪一舷。

## 炮口位置

炮弹不再从固定屏幕坐标生成。

每门炮使用自己的 `muzzleLocal`：

- 轴向坐标来自其 cannon cell 中心。
- 横向坐标放在船体该侧的外缘附近。
- 转换到世界坐标后作为 `V8Projectile.spawn()` 的 x/y。

因此船体旋转后，炮口和弹道会随船一起旋转。

## 射界

每门炮不是 360° 炮塔。

基础舷侧法线：

- 玩家 starboard = local +X，port = local -X。
- 敌舰 starboard = local +Y，port = local -Y。

每门炮按其轴向位置获得约 `-12° ... +12°` 的 `arcOffset`。

规则：

- 单炮可开火：目标方向与该炮自身舷侧方向误差 <= 38°。
- 完整齐射区：目标与整条舷侧正法线误差 <= 22°。
- 22°–46° 属于边缘射界，只允许实际能指向目标的部分炮位参与。
- >46°：该舷不能开火。

这样船体角度会直接决定“一轮能打几门”。

## 玩家转向

V10.3 不引入完整航行位移，只增加原地/低速航向调整，保证玩家可以主动把舷侧对准目标。

输入：

- 移动端：`↶ 左转`、`右转 ↷` 两个按住式按钮。
- 键盘：A / ← 左转，D / → 右转。

基础转速：约 38°/秒。

如果舵机已被摧毁，仍允许极慢转向以避免软锁，但最大转速降到约 35%。

船体旋转继续使用已有 `ship.rotation`，因此碰撞、世界/局部坐标、进水横倾和矢量船体渲染自动跟随。

## 玩家真实齐射

现有自动攻击节奏继续保留，但 `startPlayerSalvo()` 不再固定创建 4 发。

触发过程：

1. 找到当前目标和瞄准点。
2. 根据目标局部位置选择 port/starboard。
3. 读取该舷所有存活且装填完成的炮。
4. 过滤射界不满足的炮位。
5. 若 0 门可射，则本轮不创建 salvo，并在 HUD 显示 `目标不在舷侧射界`。
6. 按炮位轴向顺序形成 shot queue。
7. 逐门间隔 0.085 秒点火。
8. 每一门炮从自己的世界炮口发射。
9. 每发炮弹继续走 V10.2 的 ammoType / armor / first-layer / fracture / fire 流程。
10. 每门炮开火后进入独立 reload。

玩家炮 reloadMax：约 1.85 秒。

如果一轮开始后某炮位在轮到它之前被击毁，该炮直接跳过，不生成炮弹。

## 敌舰真实齐射

敌舰不再在接近过程中始终“船头对玩家直接开炮”。

行为：

1. 远距离接近时保持当前前进方向。
2. 到达战斗距离后，根据玩家位置选择最近的舷侧。
3. 平滑转向，让该舷正法线朝向玩家。
4. 只有进入边缘射界后才允许开火。
5. 敌舰一轮同样按真实存活炮位逐门点火。
6. 敌舰炮弹 ammoType 保持 `standard`。

转向速度：

- sloop：约 32°/秒。
- gunship：约 25°/秒。
- manowar：约 18°/秒。

敌舰 reload：

- sloop：2.45 秒。
- gunship：2.75 秒。
- manowar：3.15 秒。

舵机毁坏后转向速度乘 0.35。

## 单炮弹道

每一门炮都瞄准当前 `currentAimPoint()` 或敌舰随机玩家活格。

允许很小的炮位散布以避免所有弹道完全重合，但：

- 不改变玩家 32 / 敌舰 22 的浅弧硬上限。
- 不改变一炮一层。
- 不增加多段穿透。

## 炮位损毁

真实 cannon cell 被命中并 HP 归零后：

- 对应 gun slot 立即失效。
- 下一轮齐射门数减少。
- 如果它正在本轮 shot queue 中但尚未发射，跳过。
- 不影响另一舷炮组。
- HUD 的该舷存活炮数即时下降。

因此链弹对外露炮位具有实际战术价值。

## 装填

每门炮独立维护 `reload`。

每帧只对已存在 gun slot 做简单减法：

```text
reload = max(0, reload - dt)
```

不开全船扫描；battery 建立后直接遍历最多 14 门炮/船。

玩家/敌舰 salvo 只能选择 `reload <= 0` 的活炮。

## 后坐力与视觉

每门炮发射时：

- 产生现有 `muzzle` 火光。
- 新增轻量 `muzzleSmoke`，持续约 0.45–0.65 秒。
- 炮口烟沿舷侧外法线扩散。
- 给 `ship.physics` 添加很小的反向 impulse 和角动量。

一整舷连续点火会形成从船首到船尾的火光/白烟波，而不是四个固定位置同时闪烁。

FX 保持全局上限；`muzzleSmoke` 不使用粒子系统，每炮只创建 1 个轻量对象。

## HUD / UI

玩家状态区新增：

```text
左舷 7/7 · 右舷 5/7
当前射界：右舷 4 门可射
```

目标不在射界：

```text
当前射界：无 · 请转舵
```

转舵控制面板显示当前船体航向角，不增加速度/帆控等其他功能。

V10.2 的弹药按钮保持原位置和功能。

## 与 V10.2 弹药的关系

每门玩家炮发射时仍通过当前 `P.spawn` wrapper 获得：

```text
attackPower = 当前 24–240 炮攻
ammoType = 当前玩家弹药
```

因此：

- 实心弹齐射 = 多门真实炮位同时做高穿甲单点打击。
- 链弹齐射 = 多门真实炮位对桅杆/舵/炮位形成功能打击。
- 爆裂弹齐射 = 多个真实着弹点制造大面积疲劳/裂纹/起火。

V10.3 不修改三种弹药倍率。

## 性能边界

- 单船 gun slot 上限 14。
- 同时活跃敌舰维持现有数量级。
- 每帧装填更新只遍历 gun slot，不扫描全船 cells。
- shot queue 只保存本轮要发射的 gun id。
- 每炮 1 个 muzzle + 最多 1 个 muzzleSmoke。
- 不创建持续物理炮架刚体。
- 不提高当前结构求解、裂缝、残骸或水模拟频率。

## 失败/边界行为

- 一舷全部炮毁：该舷永远不能开火，另一舷不受影响。
- 两舷全部炮毁：玩家仍可转向/瞄准，但不再产生炮弹；敌舰同样失去火力。
- salvo 中途目标沉没：取消剩余 shot queue，不自动把这一轮剩余炮弹切到另一艘船。
- salvo 中途炮位被毁：跳过该炮。
- 玩家切弹发生在齐射进行中：尚未生成的后续炮弹继续遵循 V10.2“新生成炮弹读取当前弹种”的规则；已经在空中的炮弹绝不改变。
- 舵毁坏：允许 35% 极慢转向，避免无法把剩余舷炮对准任何目标的软锁。

## 测试要求

新增 V10.3 专用回归，至少覆盖：

1. battery 数量和左右舷分配正确。
2. 每个 gun slot 绑定真实 cannon cell。
3. 炮位毁坏后对应舷下一轮少一发。
4. port/starboard 独立，不共享损毁状态。
5. 满足完整射界时玩家可使用该舷全部 ready 炮。
6. 边缘射界只允许部分炮开火。
7. 超过 46° 时不能开火。
8. 炮弹从各自真实炮口位置生成，不再固定 `x=610` / 三个 y 坐标。
9. 逐门间隔约 0.085 秒，顺序稳定。
10. 每门炮有独立 reload。
11. 敌舰在开火前会转到舷侧射界。
12. 敌舰炮弹保持 standard。
13. 玩家每发仍携带当前 V10.2 ammoType 和炮攻。
14. 一炮一层、浅弧 32/22 不退化。
15. cannon cell 被链弹击中仍使用 V10.2 cannon 倍率。
16. V10.2、V10.1、V10.0、V9.9、V9.8、V9/V8 全量回归继续通过。
17. 全部 `js/v8/*.js` 语法检查通过。
18. GitHub Pages 必须对最终 main SHA 部署成功后才能宣布发布。

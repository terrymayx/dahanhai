# V9.9 · 真实船体结构与浮力破坏系统 — 设计规格

## 目标

把 V9.8 的“炮攻 → 装甲 → 穿透 → 局部爆炸”升级为事件驱动的真实破坏链：炮弹命中后考虑入射角、局部装甲疲劳和材料断裂；结构损伤会重新分配局部承载；只有与外海连通的破口才会进水；不同舱室独立积水并改变重心、浮力中心、横倾和纵倾；大块结构断裂后保留独立漂浮/下沉状态。

## 不变约束

1. 保留当前 8px 物理网格，不回退到 6px，也不引入每帧全船有限元或流体求解。
2. 保留“一发炮弹只命中最前一个物理层”的硬规则。重度穿透不会让同一发炮弹继续穿过后面的活格；只有前层已经被之前的炮击真正打出洞，后续炮弹才可能继续飞入内部。
3. 保留 V9.8 手动炮攻 24–240、AUTO 可选、攻击力决定爆炸范围、火灾系统、结构清理系统和矢量船体缓存。
4. 所有昂贵计算都由事件触发：命中、格子毁坏、结构超载、破口拓扑变化、舱室水量跨阈值或大块断裂。正常航行不扫描整艘船。
5. 移动端优先。任何新系统都必须有明确的局部扫描半径、上限或缓存策略。

## 1. 局部材料与装甲疲劳

### 1.1 新增格子状态

每个物理格在首次被 V9.9 初始化时获得：

- `armorMax`: 初始装甲强度，来源于 V9.8 `armorFor(ship, cell)`。
- `armorHp`: 当前装甲剩余值。
- `fracture`: 0–1，材料裂纹程度。
- `fatigue`: 0–1，反复受冲击产生的疲劳。
- `structuralCapacity`: 结构承载上限；hull/deck 较低，beam/core 最高。
- `structuralStress`: 当前局部估计应力。

### 1.2 装甲削弱规则

一次直接命中先计算等效装甲，再计算本次装甲消耗：

`armorLoss = attackPower * impactFactor * materialFactor`

其中：

- `impactFactor` 由入射角决定，正撞高、斜击低。
- `materialFactor`：deck/powder/mast 更容易剥落；beam/core 更耐打。

装甲不会因为一次普通命中直接变为 0；但重度穿透允许显著剥落。`armorHp / armorMax` 会影响下一次 `effectiveArmor`。

### 1.3 裂纹与疲劳

- `fracture` 主要来自超过当前装甲承受能力的单次冲击。
- `fatigue` 主要来自同一区域反复受击。
- 两者都会降低后续等效装甲和结构承载。
- 相邻 1–2 格只获得少量冲击疲劳，不做整船传播。

## 2. 入射角与等效装甲

### 2.1 表面法线

命中的首层格根据其临空邻边估算局部外表面法线。若多个方向同时临空，则取这些方向向量的归一化平均；内部格没有明确外表面时退化为朝炮弹来向的反方向，保证数值稳定。

### 2.2 入射角

使用炮弹速度向量与局部外法线计算 `impactCos = abs(dot(-velocityDir, normal))`。

- `impactCos >= 0.75`：接近正撞。
- `0.35 <= impactCos < 0.75`：斜击。
- `impactCos < 0.35`：浅角擦击/跳弹候选。

### 2.3 等效装甲

`effectiveArmor = currentArmor / max(0.35, impactCos)`

这样斜角会增加需要克服的等效厚度，同时把极端浅角限制在合理上限，避免无穷大。

### 2.4 跳弹

仅直接炮弹命中允许跳弹：

- `impactCos < 0.28`
- 且 `attackPower < effectiveArmor * 1.10`

则判定 `ricochet`。炮弹反射速度后继续飞行，但本次已经消耗明显动能：速度乘 0.55，攻击力乘 0.45；同一发炮弹最多跳弹一次，防止无限反弹。

若不是跳弹，则维持 V9.8 首层命中后立即死亡的规则。

## 3. 结构承重与疲劳断裂

### 3.1 结构节点

结构计算只关心活着的 hull/deck/beam/core 格。每种类型给一个基础承载：

- deck: 1.0
- hull: 1.4
- beam: 3.4
- core: 4.2

实际承载乘以下系数：

- `hp / maxHp`
- `1 - fracture * 0.55`
- `1 - fatigue * 0.35`

### 3.2 局部重量估计

命中或结构格毁坏后，以受击点为中心，仅在曼哈顿/方形半径 9 格内建立局部图。每个节点的负担由其后方可达的非结构/结构活格数量和 `CELL_WEIGHT` 汇总估算。

不做全船真实有限元。目标是捕捉“单薄连接承载大块船体”这一关键现象。

### 3.3 超载规则

若某结构节点 `stress / capacity > 1`：

- 增加 `fatigue` 和 `fracture`。
- 比值超过 1.35 时允许直接造成额外结构伤害。
- beam/core 比 hull/deck 更耐瞬时冲击，但一旦长期超载也会断。

一次结构事件最多处理 12 个超载节点，避免连锁雪崩造成卡顿。

### 3.4 大块断裂

现有 `detachDisconnectedComponents` 保留，但 V9.9 在组件断开后按质量分类：

- `< 10%` 原船活质量：仍按普通碎片/残骸处理。
- `>= 10%`：创建 `structuralChunks` 独立大块。

大块保存：

- 原格子相对坐标和材料类型。
- 质量、估算浮力、当前水量。
- 世界位置、旋转、线速度、角速度。
- 独立漂浮时间和下沉进度。

大块不再参与炮弹精细命中，避免把系统复杂度翻倍；它属于高质量视觉/浮力残骸。

## 4. 外海连通破口

### 4.1 核心规则

只有满足以下条件的死亡格才算“海水破口”：

1. 类型是 hull/deck/beam/core 中可形成通道的格子；
2. 该死亡格通过死亡格通道可以连到船体包围盒外部；
3. 或死亡格本身在原始物理包络边界上。

内部主梁单独炸毁不会直接注册漏点。

### 4.2 外海连通搜索

结构拓扑改变时，以新死亡格为起点做局部 flood-fill：

- 最大搜索半径 14 格。
- 只沿死亡/空格传播。
- 一旦走出原物理占用包围区域，判定与外海连通。

结果缓存到 `cell.__v99OpenWater`，并用伤害 revision 失效。

## 5. 舱室局部进水

### 5.1 舱室数量

按船型沿纵轴划分固定逻辑舱：

- sloop: 4
- gunship: 5
- manowar: 6
- player: 8

这是逻辑分区，不增加物理格。

### 5.2 舱室数据

每个舱室：

- `water`: 0–1
- `capacityWeight`: 该舱原始格权重
- `breachWeight`: 当前外海连通破口权重
- `centerLocal`: 舱室局部中心

### 5.3 进水率

`rate = breachWeight * baseLeak * pressure * exposure`

其中：

- `pressure` 随该舱 water 上升略增加，但有上限。
- `exposure` 由破口距船体中线和当前吃水姿态近似修正。

舱室之间默认不自动均匀。只有相邻舱室之间存在已毁坏的内部通道时，才以较低速率串水。

### 5.4 总进水

兼容旧 HUD：

`ship.floodLevel = sum(water * capacityWeight) / sum(capacityWeight)`

旧系统仍可读取 `floodLevel`，但 V9.9 不再把它作为唯一姿态来源。

## 6. 重心与浮力中心

### 6.1 重心

基础重心来自所有活格和其 `CELL_WEIGHT`。为了性能，只在结构 revision 变化时重算。

舱室积水额外作为水质量加入重心。

### 6.2 浮力中心

每个舱室的有效浮力：

`buoyancy = intactVolume * (1 - water)`

浮力中心由各舱室 `centerLocal` 按 buoyancy 加权。

### 6.3 横倾与纵倾

重心与浮力中心的横向差产生横倾目标，纵向差产生船头/船尾吃水差。

- 横倾目标限制在 ±0.22 rad 左右，超过阈值进入侧翻危险区。
- 纵倾主要表现为 `sinkOffset` 与轻微 pitch-like 2D 位移，不引入真正 3D 旋转。
- 姿态用阻尼平滑追踪目标，避免每帧抖动。

### 6.4 沉没/翻覆判据

不再使用“flood >= 0.985 就沉”。改为：

- 有效总浮力持续低于总重量阈值一段时间 → 渐进沉没。
- 横倾绝对值持续超过 0.20 rad 且一侧舱室高积水 → 侧翻沉没。
- 主结构完整度极低且存在大型断裂 → 结构失效沉没。

必须使用短暂持续时间门槛，防止单帧尖峰触发。

## 7. 火药舱与内部爆炸

火药舱爆炸继续使用局部范围，但改为对附近结构节点增加高 `fracture` 与 `fatigue`，而不是直接用超大固定伤害删除结构。

如果爆炸区域已有外海破口，爆炸后的新死亡格可立即改变舱室进水；如果结构完整，则主要体现为大洞、裂纹和局部超载。

## 8. 渲染与反馈

### 8.1 装甲疲劳可视化

不增加网格轮廓。只在现有矢量损伤叠加层里根据 `fracture`/`armorHp`：

- 轻裂：细短裂纹。
- 中裂：深色裂纹 + 少量剥落。
- 重裂：明显焦黑/木板破碎边缘。

### 8.2 船体姿态

V9.9 姿态模块覆盖旧 V9.7 flood pose 的横倾计算，但保留其接口兼容字段：

- `__v97FloodRoll`
- `__v97FloodSinkOffset`

这些字段由 V9.9 浮力结果写入，避免其它渲染器失效。

### 8.3 HUD

锁定目标时在现有穿透预览基础上增加：

- 当前局部装甲 / 初始装甲
- 入射角
- 等效装甲
- 穿透结果

状态栏增加简化的 `舱水` 指示，例如 `舱水 8/31/4/0%`，移动端只显示最高两个舱室水量，避免占屏。

## 10. 测试与发布门槛

新增 V9.9 专用 CI，至少覆盖：

1. 同一格连续命中后 `armorHp` 下降，后续等效装甲更低。
2. 斜击等效装甲高于正撞；浅角弱炮触发一次跳弹。
3. 非跳弹命中仍满足“一发一层”，炮弹命中后死亡。
4. 内部 beam/core 单独死亡不会产生外海漏点。
5. 外壳死亡并与外海连通后只给对应舱室增加 breach。
6. 一侧舱室大量进水会产生同侧横倾；对称进水横倾接近 0。
7. 船尾/船头局部高进水产生纵向吃水差。
8. 局部承重超载会增加 fatigue/fracture，并可触发结构断裂。
9. >=10% 质量的断裂组件进入 `structuralChunks`，小块保持旧碎片逻辑。
10. 所有新增/修改 JS 用 `node --check` 通过。
11. `index.html` 加载顺序正确，所有正式脚本缓存参数为 `9.9.0`。
12. GitHub Pages 对最终发布 commit 部署成功。

## 11. 成功标准

玩家可肉眼和逻辑上观察到以下因果链：连续炮击同一点会削薄装甲；斜射更难穿透；只有外壳真正开洞才进水；右舷破洞会让右侧舱室先积水并产生右倾；主梁在局部承载过高时会逐渐疲劳并断裂；大型断裂段不会瞬间消失，而会作为独立残骸漂浮、倾斜并最终下沉。
